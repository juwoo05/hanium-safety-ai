# 건설 안전 도메인 코드 리뷰

## Trigger
"리뷰", "review", "코드 확인"이 포함되고 도메인 관련 코드(위험요소, 조치, 보고서, 원청, 하청, 현장)가 대상일 때 이 스킬을 사용한다.

## Instructions

수행계획서 기반 건설 안전 플랫폼(안전고리) 도메인 규칙으로 리뷰한다.
Critical → Warning → Suggestion 순으로 출력하고, 각 항목에 파일명:라인번호를 포함한다.

---

### 도메인 규칙

**조치 상태 흐름**
- 조치 상태는 반드시 `요청중 → 진행중 → 완료` 3단계만 허용한다.
- 역방향 전이(완료 → 진행중 등)를 방지하는 검증이 있어야 한다.
- 완료 처리 시 완료 사진(이미지 URL) 필드가 필수다.

**원청/하청 권한 분리**
- 원청(ROLE_PRIME)만 위험요소 등록·삭제·담당 하청 지정이 가능하다.
- 하청(ROLE_SUB)은 자신에게 배정된 위험요소의 조치 상태만 변경 가능하다.
- 현장관리자(ROLE_MANAGER)는 전체 현황 조회 및 보고서 생성 권한을 가진다.
- 역할 체크 없이 상태를 변경하는 엔드포인트가 있으면 Critical.

**SMS 알림 (Amazon SNS)**
- 조치 기한(`dueDate`) 초과 시 SNS 발송 로직이 존재해야 한다.
- SNS 발송 실패가 전체 트랜잭션을 롤백시키면 안 된다 (비동기 처리 필요).
- 기한 초과 후에도 미이행이면 신고 게시판 자동 등록 로직이 이어져야 한다.

**신고 게시판 자동 등록**
- SMS 발송 후에도 `N일` 이상 미이행이면 `ReportBoard`에 자동 등록되어야 한다.
- 자동 등록 항목은 원청·하청 양쪽 모두 조회 가능해야 한다.

**보고서 생성**
- 안전관리 보고서에는 현장 정보, 위험요소 목록, 항목별 조치 내역이 모두 포함되어야 한다.
- 보고서 공유는 링크 또는 메일 방식을 지원해야 한다.
- MCP로 생성된 보고서 내용이 DB에 메타데이터로 저장되어야 한다.

**위험요소 분석 결과 저장**
- FastAPI에서 받은 분석 결과(`riskItems`)는 Spring Boot가 MariaDB에 저장한다.
- 분석 결과에는 위험요소명, 관련 법규 근거, 즉시 조치 항목이 포함되어야 한다.

### 체크리스트 (리뷰 시 반드시 확인)

- [ ] 조치 상태 전이 검증 로직 존재 여부
- [ ] 역할(ROLE_PRIME / ROLE_SUB / ROLE_MANAGER) 기반 접근 제어
- [ ] `dueDate` 초과 감지 및 SNS 비동기 발송 처리
- [ ] 신고 게시판 자동 등록 연계 여부
- [ ] 보고서 생성 시 필수 필드 누락 여부
- [ ] FastAPI ↔ Spring Boot 인터페이스 필드명·타입 일치 여부
